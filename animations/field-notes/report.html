1. Task description

A cohesive visual landing page adapts seven supplied GSAP examples to the user's photographs. The site theme is preserved exactly, with no external assets or extra runtime build step. The brief follows verbatim. 

You are a senior front-end developer with deep expertise in GSAP (GreenSock Animation Platform) and modern landing-page construction.

Build a single animated web page using GSAP. The page should be production-ready and run in a modern browser with no build step required beyond what the existing project already uses.

**Reference material**

- Use the GSAP demo examples in the `GSAP-Demos` directory as the source for animation techniques. Each example has a video demonstrating the motion and a `.md` description explaining how it works. Study both the video and the description for every example you draw from, and reproduce the behavior they show, adapting it to this page's content.
- Use images from the `source-images` directory wherever imagery is needed on the page. Do not introduce external or placeholder images.

**Animation requirements**

- Combine animations from the `GSAP-Demos` examples in any order and arrangement that makes the page feel cohesive. You are free to sequence, layer, and pace them as you see fit, but every animation should serve the page's flow rather than feel like an isolated demo.
- Use GSAP's timeline and ScrollTrigger capabilities where they make the motion cleaner, and keep the total animation duration and easing consistent so the page feels like one piece.

**Visual constraints**

- Keep the existing color theme exactly as it currently is. Do not introduce new brand colors, change the palette, or alter the existing color tokens. Inspect the current styles in the project and match them.

**Output**

- Deliver the complete page: markup, styles, and the GSAP script, wired to the referenced assets and the existing theme.
- Make sure every animation you use is traceable to an example in `GSAP-Demos`, and that all `source-images` paths resolve correctly.

3. Solution architecture

GSAP 3.15.0, ScrollTrigger, Flip and SplitText are local ES modules, copied from the installed repository package. GSAP 3.15.1 was checked as the current release; dependencies were not changed. DOM, CSS perspective and image clipping are sufficient. The existing Vite pipeline bundles the integrated page; a standalone HTTP-served page needs no build.

sections.html is shared content; style.css scopes every rule to the component; animation.js exports CONFIG and mountAnimation(container, options), returning play, pause, destroy. vendor/ contains the required GSAP modules, assets/ contains original-name copies of source-images. sync-page.py writes the standalone index and the named Nunjucks page, converting image paths for Vite.

The motion is paced by scroll rather than autonomous loops. Bento, mask, wave and gallery use labeled, scrubbed timelines with linear scroll mapping. Pointer tilt uses a 0.5s power2.out lag; direct carousel transitions use a consistent 0.6s power2.inOut ease. Gallery entry spans timeline units 0–0.66, lateral travel 0.35–2.55, departure 2.55–3.21. These units are normalized against scroll distance, not wall-clock seconds.

ResizeObserver measures the container. Compact motion shortens pin ranges and retains native access to all cards. Reduced motion and Pause remove pins and restore readable static layouts. Keyboard controls, alt text, real-text wave alternatives, visible focus rings and live carousel status are included. No ambient ticker, shader, external font or network library is used. Geometry is cached for per-frame glyph movement; image dimensions cap central bento enlargement.

Carousel continuity correction

A frame-by-frame comparison with the first transition in the reference video identified a 984px next-transition snap caused by removing three cards from grid flow. The correction keeps all cards in flow, positions the wrapping copy relative to its window, and drives FLIP, the outgoing copy, and incoming card on one timeline. It includes the card gap in travel distance and reproduces the temporary edge shrink. Duration is 0.6s. Desktop maximum visible frame displacement fell to about 33px; normalized displacement fell from 3.21 to 0.11 card widths per 16.67ms. The row height stays fixed. Both directions, rapid queued input, mid-transition pause and resize, and reduced motion were tested at 375px, 768px, and 1440px. Traces are in checks/carousel-before-results.json and checks/carousel-after-results.json; 50ms reference/adaptation sheets are in .reanimate/field-notes/carousel-comparison. The earlier page-wide captures predate this correction.

Curve swipe footer

The Curve swipe recording and descriptions were studied at 20fps. The footer now pins and scrubs the curved SVG panel through its rise, covered hold, and downward return. The action button has been removed. Its 0.65/0.8/0.5 phase weights map onto 1.4 viewport heights of scroll; the end is clamped so the full sequence is reachable. Stopping scroll holds the shape and reverse scrolling reverses the sequence. The reference colors are replaced with existing theme tokens; no brand palette changes were made. Scroll progress, idle hold, reverse behavior, pause, reduced motion, lifecycle cleanup, responsive layouts, and the integrated route are checked in checks/curve-results.json. Reference frames and adapted recordings are retained separately.

Custom load-time hero text reveal

7. Assumptions and limitations

  • Seven examples selected; remaining three unused to maintain a coherent editorial narrative.
  • Field Notes is a fictional visual journal, not a travel booking service.
  • Scroll behavior is adapted to the page proportions; video scroll speed is user-controlled, not a fixed playback duration.
  • Existing theme tokens are inherited unchanged. Photographic colors are retained from supplied images.
  • Image Mask uses two supplied still photographs in place of the reference moving action footage.
  • No external image, font, library, or API requests are required.
  • Compact containers use shorter pin distances; reduced motion and Pause remove pinning and show all content.

Unused demo directories: MotionPath Waypoints, Pinned panels with overscroll, Shader on Scroll. They are not part of this page. Long-task results are a short headless-Chrome sample, not a guarantee for every device. All work remains local; no deployment or commit was performed. Full details and commands are in README.md.
